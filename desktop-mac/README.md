# deepDB for macOS

A standalone macOS desktop app for **deepDB** — the static database-design teaching site in the
repository root. It is the macOS counterpart of the Windows wrapper in `../desktop`:

- the site is served from a loopback HTTP server bundled inside the app (stable origin, so saved
  models survive restarts), and opened in a frameless Electron window;
- the window chrome is macOS-native in spirit: custom traffic lights in the top-left, a real
  macOS menu bar, an About panel, window-state restore, single instance, Dock behaviour;
- the website source is **not modified**. `build/prepare.mjs` copies the untouched
  `index.html`, `assets/` and `README.md` into `web/` at build time and adds exactly one file,
  `desktop-mac.css`.

```
desktop-mac/
├── main.js                     Electron main process: server, window, menu, IPC, lifecycle
├── preload.js                  context-isolated bridge: traffic lights, chrome CSS, key shims
├── desktop-mac.css             window chrome styles (dots, drag regions, insets, fullscreen)
├── build/
│   ├── prepare.mjs             copies the untouched site into web/
│   ├── make-icon.cjs           regenerates build/icon.png from the site's brand assets
│   ├── make-icns.cjs           converts build/icon.png into build/icon.icns for mac builds
│   ├── make-mac-bundle.cjs     Windows-only fallback: assembles a .app ZIP from the official zip
│   ├── entitlements.mac.plist  hardened-runtime entitlements (JIT / executable memory)
│   ├── icon.png                1024×1024 app icon
│   └── icon.icns               app icon, generated from icon.png
├── _mac-build/                 files added to the Windows-assembled ZIP (first-run .command + README)
├── .gitignore                  node_modules/, web/, dist/
├── package.json                scripts + electron-builder configuration
├── package-lock.json           pinned dependency tree (used by `npm ci` in CI)
└── web/                        generated by `npm run prepare:web` (gitignored)
```

## Requirements

- macOS 11 or newer (Apple Silicon or Intel) to build and run the packaged app;
- Node.js 20+ and Xcode Command Line Tools (`xcode-select --install`) on the build machine;
- no runtime dependencies: the site is static, and Electron is bundled by electron-builder.

## Development

```bash
cd desktop-mac
npm install
npm start                 # copies the site into web/ and launches Electron
```

`npm start` always refreshes `web/` first, so edits in the repository root are picked up.

## Building the app

Run these on a Mac — electron-builder needs macOS to sign, package and notarize:

```bash
npm run build:mac            # arm64 + x64: two .dmg and two .zip files
npm run build:mac:arm64      # Apple Silicon only
npm run build:mac:x64        # Intel only
npm run build:mac:universal  # one universal .app (built via @electron/universal)
```

Artifacts land in `dist/`:

```
deepDB-1.5.20-macos-arm64.dmg
deepDB-1.5.20-macos-x64.dmg
deepDB-1.5.20-macos-arm64.zip
deepDB-1.5.20-macos-x64.zip
```

### Signing

The default configuration uses **ad-hoc signing** (`"identity": "-"`), which is what an unsigned
open-source Mac app needs to launch on Apple Silicon at all. It is not notarized, so Gatekeeper
warns on first launch (see below).

For a proper Developer ID build, export your credentials and override the identity/notarization
on the command line — no file changes needed:

```bash
export CSC_LINK=/path/to/developer-id.p12 CSC_KEY_PASSWORD='…'
export APPLE_ID='you@example.com' APPLE_APP_SPECIFIC_PASSWORD='…' APPLE_TEAM_ID='…'
npx electron-builder --mac --arm64 --x64 \
  -c.mac.identity="Developer ID Application: Your Name (TEAMID)" \
  -c.mac.notarize=true
```

### First launch of an unsigned build

1. Open the `.dmg`, drag **deepDB** into `/Applications`.
2. Right-click **deepDB → Open → Open** (only the first time), or use
   **System Settings → Privacy & Security → Open Anyway**.
3. If a *downloaded* copy reports “deepDB is damaged”:

   ```bash
   xattr -dr com.apple.quarantine /Applications/deepDB.app
   ```

## Windows emergency cross-build (no Mac available)

electron-builder cannot produce a macOS bundle on Windows: code signing and the `dmg` target need
macOS, and the symlinks inside the Electron framework cannot be created on Windows without admin
rights. `build/make-mac-bundle.cjs` is a small zero-dependency fallback that assembles a runnable
`.app` ZIP from the official Electron darwin zip:

```bash
npm run prepare:web
npm run icon:icns                 # build/icon.png -> build/icon.icns
node build/make-mac-bundle.cjs \
  --electron path/to/electron-v45.1.0-darwin-arm64.zip \
  --payload . --icon build/icon.icns \
  --out deepDB-1.5.20-macos-arm64.zip --arch arm64
node build/make-mac-bundle.cjs --verify deepDB-1.5.20-macos-arm64.zip
```

The ZIP keeps unix permissions and writes real symlink entries, so macOS Archive Utility recreates
the framework layout. Since Windows cannot code-sign, the ZIP also ships
`首次打开 deepDB.command` and `README-中文.txt` (from `_mac-build/`): the user runs the command once
on the Mac to clear quarantine, apply an ad-hoc signature and open the app. This path is strictly an
emergency fallback — the electron-builder / CI route above is the supported one.

## GitHub Actions

`.github/workflows/build-macos.yml` builds both architectures on a GitHub-hosted macOS runner and
uploads the `.dmg`/`.zip` files as workflow artifacts. It is `workflow_dispatch` + tag triggered and
intentionally does **not** create a GitHub release (project rule: release only on explicit request).

## What the app adds on top of the site

- **Loopback server** (`127.0.0.1`, starting at port 17872, 20 ports tried) — keeps a stable origin
  so `designerdb:v1:*` localStorage models, language and accent always survive a restart.
- **Frameless window + custom traffic lights**: red closes the window, yellow minimizes, green
  zooms (maximizes/restores); double-clicking the empty title-bar strip also zooms; when the window
  loses focus the dots gray out like macOS does. Fullscreen hides the controls and gives the header
  its original left padding back.
- **Real macOS menu bar**:
  - *deepDB*: About deepDB, Settings… (`⌘,`), Services, Hide deepDB (`⌘H`), Hide Others,
    Show All, Quit deepDB (`⌘Q`);
  - *File*: Close Window (`⌘W`);
  - *Edit*: Cut, Copy, Paste, Select All only — **no Undo/Redo menu roles**, because a menu
    accelerator would swallow `⌘Z` before the canvas sees it and break model undo;
  - *View*: Toggle Full Screen (`⌃⌘F`);
  - *Window*: Minimize, Zoom, Bring All to Front;
  - *Help*: website, GitHub repository, inspiration note.
- **Settings…** opens the site's own Settings dialog (motion switch + accent colors) by clicking
  its header/home trigger, without changing any site code.
- **Text-field undo/redo** is shimmed from the preload (`⌘Z`, `⇧⌘Z`, `⌘Y`) and routed through
  `webContents.undo()/redo()`, so native field editing works while canvas undo stays untouched.
- **Window state** (position, content size, maximized) is persisted in
  `~/Library/Application Support/deepDB/window-state.json`; saved positions that no longer land on a
  connected display are dropped and the window is centered.
- **Single instance**: launching again focuses/restores the existing window. Closing the window
  keeps the app alive (macOS convention); clicking the Dock icon reopens it.
- **External links** open in the default browser; in-app navigation is restricted to the local
  origin. No telemetry, no network calls of its own — same offline-first promise as the site.

## Previewing the macOS chrome on Windows/Linux

The production `main.js`/`preload.js` also run off macOS with the mac-only APIs guarded, which is how
the chrome was visually verified here. Useful switches:

```bash
DEEP_DB_DESKTOP_PREVIEW=1  # render the macOS traffic lights + CSS on Windows/Linux
DEEP_DB_DESKTOP_MENU=1     # install the application menu (validates the menu template)
DEEP_DB_DESKTOP_DEV=1      # open DevTools on launch
```

## Notes and limitations

- The repository rule “only release when the user asks” applies: don't tag, publish or push this
  folder unless asked.
- `web/`, `node_modules/` and `dist/` are gitignored; `web/` is rebuilt by every build script.
- The packaged `.dmg`/`.app` must be produced on macOS. This folder has been exercised through the
  Windows preview (server, window, menu template, settings shortcut, layouts at 1440×900, 1024×700
  and 960×640); the final signing/notarization step still needs a Mac or the CI workflow.
- No auto-updater. The app is a teaching site; updates mean replacing the app bundle. The Windows
  wrapper gained in-app updates in v1.5.20, but that path is Windows-only on purpose: this mac build
  is ad-hoc signed, so a downloaded update could not be verified and would be blocked by Gatekeeper.
  Grab a new ZIP when a new release is published instead.
